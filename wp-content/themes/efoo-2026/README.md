# efoo 2026 テーマ

efoo株式会社のコーポレートサイトの自作テーマ。デザインカンバス「efoo.jp リデザイン案」の案A（Light Tech）を実装したものである。トップページのほか、お知らせ一覧・詳細、固定ページ、404、検索結果の専用テンプレートを持つ。

## 構成

- `front-page.php` — トップページ。ヒーロー（タイピング・「前へ」の粒子集合・ライブ実行ターミナル・PR動画の物体検出風オーバーレイ）、二段マーキー、サービススライダー、強み、チーム、お知らせの最新5件、CTA
- `header.php`・`footer.php` — 共通のヘッダー（浮遊ピル型の追従ナビ）とフッター。ヘッダーとフッターから、会社概要・お問い合わせ・お知らせ一覧へ 1 クリックでたどれる
- `home.php`・`archive.php`・`taxonomy-portfolio.php` — お知らせ一覧（投稿ページ、portfolio_item のアーカイブ `/project/`、portfolio タクソノミーなどの分類のアーカイブ）。分類の絞り込みチップとページ送り付き
- `single.php` — 投稿・ポートフォリオの詳細。文字だけの見出し帯（分類・日付・タイトル）、帯の下端にまたがるアイキャッチ、本文、記事の終わり（同じ分類のほかの記事 3 件、お知らせ一覧へのボタン、プレスリリースと掲載実績では取材・掲載のお問い合わせへのリンク）の順に並べる。コメント欄と前後の記事へのリンクは置かない
- `page.php` — 固定ページ（会社概要・お問い合わせなど）。本文はブロック・プラグインの出力をそのまま載せ、記事詳細と同じ本文の組版（`.prose`）で表示する
- `404.php`・`search.php` — ページが見つからないときと、サイト内検索の結果（0 件のときは見つからなかったことを出す）
- `index.php` — どのテンプレートにも当たらないときの素のテンプレート
- `template-parts/` — お知らせ一覧の本体（`news-list.php`）とその 1 行（`news-row.php`。記事詳細の「ほかの〈分類〉」も使う）、分類の絞り込みチップ（`category-chips.php`）、検索フォーム（`search-form.php`）
- `functions.php` — テーマの機能（title-tag・アイキャッチ・フィードのリンク）、本文中の裸の URL のリンク化、アセットの読み込み、URL を引く関数、記事詳細の出し分けに使う関数
- `assets/css/main.css` — カラー・余白・ヘッダーの高さのトークン、レイアウトのクラス、動きの定義、狭い画面のブレークポイント
- `assets/js/main.js` — メニューの開閉、タイピング、粒子生成、ターミナルのループ、動画の検出枠（カット時刻・座標は実映像から採寸）、スライダー
- `assets/img/` — Lシフトの画面素材（l-shift リポジトリ由来）、エディタ画像、動画のフレーム

写真・PR動画は WordPress のメディア（`wp-content/uploads`）を参照する。ローカルでは `pnpm env:pull` 済みであれば同じパスで表示される。

## データとリンクの決まり

- お知らせ・掲載実績の記事は、wpzoom-portfolio の投稿タイプ `portfolio_item` と、その分類 `portfolio` に入っている。トップのお知らせは `portfolio_item` の新しい順に 5 件を出す（`efoo_news_post_types()`）。通常の投稿はお知らせの一覧には出さないが、個別ページ・検索結果・フィードではこれまでどおり扱う
- お知らせ一覧の URL は `efoo_news_index_url()` が `portfolio_item` のアーカイブから引く（無ければ投稿ページ、それも無ければトップ）
- 会社概要は固定ページのスラッグ `company`、お問い合わせは `contact-us`（無ければ `contact`、タイトル「お問い合わせ」の順）から URL を引く（`efoo_company_url()`・`efoo_contact_url()`）。会社概要のページが無いときは、ヘッダーとフッターにリンクを出さない
- 記事詳細の役割は、portfolio の分類の term ID で決める（`efoo_entry_role()`。プレスリリース 16 → `press`、掲載実績 19 → `media`、シェフレピ店長ブログ 18 → `blog`、それ以外と通常の投稿 → `post`）。`<article>` に `entry--<役割>` を付け、掲載実績では本文を白いカードに収めて外部記事へのリンクをボタンにする。分類を追加・付け替えたときは、この対応表を見直す
- 記事詳細のアイキャッチは、本文に同じ添付画像（`wp-image-<添付 ID>` のクラス）が入っている記事では出さない（`efoo_entry_shows_cover()`）。プレスリリースは本文の先頭付近にアイキャッチと同じ画像を入れているため、ここで出さない側になる
- 本文の見出しは h2 のほか、「太字だけの 1 項目の箇条書き」（プレスリリースが見出しの代わりに使う書き方）も h2 と同じ見た目にする。太字の後ろに文が続く項目は、太字だけが見出しになる
- フッターの SNS（X・Instagram・YouTube）は、シェフレピの公式アカウントへリンクする

## 画面幅と動き

- ブレークポイントは 2 段である。860px 以下ではヘッダーのナビを畳み、メニューボタンで開閉する（Esc・メニュー外のクリック・メニュー内のリンクで閉じる）。640px 以下をスマホ幅とし、余白・見出し・サービスのカード幅・チームの列数を詰める
- テンプレートの見た目はほとんどがインラインの `style` にある。インラインは media query で上書きできないため、幅で変わる指定だけを `main.css` のクラスに持つ。幅で変わる指定を足すときは、インラインではなくクラスに書く
- 追従ヘッダーの位置と高さは `--header-top`・`--header-h` で持ち、アンカーの着地位置（`scroll-padding-top`）もこの値から決める
- スクロール連動の出現は `animation-timeline: view()` を使い、未対応ブラウザは JS の IntersectionObserver で代替する。`prefers-reduced-motion: reduce` では出現の演出を適用せず、最初から表示する

## ローカルでの確認

`.wp-env.json` がこのテーマを wp-env にマウントしている。初回・設定変更後は wp-env の再起動が要る。`pnpm env:pull` で取り込んだ本番の DB では、このテーマが有効なので、そのまま表示を確かめられる。

```sh
pnpm env:start
```

Inspiro の表示と見比べるときは `pnpm wp theme activate inspiro`、このテーマへ戻すときは `pnpm wp theme activate efoo-2026`。ローカルの DB は `pnpm env:pull` で本番の状態に戻る。

## 本番への反映

このテーマの配置は本番への書き込みのため、ユーザーの明示指示があるときだけ行う。

配置は `scripts/deploy-theme.sh` で行う。変更を main へマージしてから、次の順に実行する。

```sh
bash scripts/deploy-theme.sh --dry-run   # 送るコミットと、本番との差分を表示するだけ
bash scripts/deploy-theme.sh --yes       # 本番へ送り、nginx のキャッシュを消して、本番を確かめる
```

- 送るのは作業ツリーではなく、`git fetch` した `origin/main` のテーマである。本番のテーマは main と一致させる。作業ツリーの未コミットの変更や、main 以外のブランチは送られない
- 送る前に、ディレクトリ 755・ファイル 644 に揃え、その権限を本番の既存ファイルにも写す。手元の umask で権限が狭いまま本番へ写ると、CSS・JS・画像が 403 になるためである。あわせて全 PHP ファイルの構文を確かめる（手元に php が無ければ本番サーバーの php を使う）
- `origin/main` に無いファイルは本番から消す。`--dry-run` の出力で `*deleting` の行がそれにあたる
- 差分は内容の checksum と権限で判定する。`--dry-run` の出力で `>f` は内容の差、`p` は権限の差である。何も出なければ差分はない
- `--yes` は送ったあとに nginx のキャッシュを消し、本番のテーマ配下の権限、`assets/` の全ファイルの URL、トップページがすべて 200 であることを確かめる。キャッシュの消去の応答が 200 でないとき（手で消す `curl` の URL を表示する）と、確認で満たさないものがあるときは、どちらも列挙し、終了コード 1 で終わる。消去が失敗しても確認は行う
- `assets/img/` の画像は URL に `?ver=` が付かないため、ブラウザに 30 日保存される（AGENTS.md の「静的ファイルの保存期間」）。画像を差し替えるときは、ファイル名を変える

本番ではこのテーマが有効である。`scripts/deploy-theme.sh` は有効・無効を変えない。有効なテーマを切り替えるのは `php ~/bin/wp --path=... theme activate <テーマ名>` で、サイト全体の表示が切り替わる。
